Bring your own agent to any website.

Today every app ships its own chatbot and pays for its own inference. AgentPort inverts that: you own one agent — on your machine, your subscription, your memory — and carry it between applications. The site lends it a few tools for one session and never learns anything else about it.

<script src="https://agentport.gogakoreli.workers.dev/connect.js"></script>

const session = await AgentPort.connect({
  name: 'Inkwell',
  tools: [{
    name: 'inkwell.document.read',
    description: 'Read the current document',
    inputSchema: { type: 'object', properties: {} },
    handler: () => ({ text: editor.value }),
  }],
  alwaysAsk: ['inkwell.document.replaceSelection'],
});

await session.prompt('Tighten the opening paragraph.');

That is the whole integration — one script tag, like adding a payment button. No API key, no model choice, no inference bill, nothing for your users to install.

Two surfaces, one agent. Connect on Inkwell, then open Tasker and connect again. It's the same agent both times, but each site's grant contains only its own tools, and closing a tab takes those capabilities away.

To try it you need an agent. Run npm run daemon on your own machine with AGENTPORT_RELAY=wss://agentport.gogakoreli.workers.dev/relay. Hit Connect agent: an installed extension wins, otherwise the AgentPort Wallet opens on its own origin. If popups are unavailable, paste the fallback code into your daemon terminal. Your agent dials out; nothing listens on your machine.

The wallet remembers; the page does not. The hosted wallet's key and real agent names stay on its own origin. After you approve the site and its requested tools, it signs an eight-hour delegation to a fresh page key. The page receives the generic label “Personal agent.”

Universal fallback: popup blocked or closed? The original code flow still works. Connection consent happens at the daemon, and gated actions keep the daemon's local approval gate.
